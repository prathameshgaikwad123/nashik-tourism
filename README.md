# NashikTourism.com

An independent, mobile-first, continuously verified guide to Nashik and the
Simhastha Kumbh Mela 2026–28. It answers two questions: *what should I do in
Nashik?* and *what do I need to know about Nashik right now?*

The site is **static HTML** served from `nashiktourism/`. There is no framework and
no runtime server. Pages are generated by small Python scripts from structured data
in `data/`; the browser enhances them with one small JavaScript file.

```
data/                  editorial source of truth (JSON) — facts, updates, events, sources…
tools/                 generators, the editor CLI, the monitor, audits and tests
  nt/                  shared library: data loading, validation, risk policy, rendering
nashiktourism/         the deployable web root (generated + hand-written pages, assets)
.github/workflows/     CI, daily rebuild, source monitor, browser QA
docs/                  deployment guide, URL inventory
reports/               generated health reports (not deployed, git-ignored)
```

## The principle

Never state unverified information as fact. Every fact that matters lives once in
`data/facts.json` with a **status** (`verified`, `reported`, `not_verified`,
`disputed`), a named source and dates, and is rendered with that status everywhere it
appears. Unknown values read *Information not yet confirmed* — never a guess.
Anything that could hurt a traveller if wrong (safety, medical, emergency, religious
dates, Kumbh rules, traffic, closures, entry, government orders, availability,
prices, passes) needs a **named human approver** before it can be live. See
`/editorial-policy/` on the site and `tools/nt/risk.py`.

## Build

```bash
python3 tools/build-all.py        # validate data, generate every page, search index, sitemap
python3 -m unittest discover -s tools/tests -v
python3 tools/seo-check.py        # SEO, structured data, every internal link and #anchor
python3 tools/content-health.py   # reports/content-health.{html,md,json}
python3 tools/qa/serve.py 8099    # serve nashiktourism/ like production (real 404s)
```

Python 3.11, standard library only. The optional browser QA (`tools/qa/*.js`) needs
Node and Playwright.

## Day-to-day editing (no HTML)

```bash
python3 tools/cms.py update new --title "…" --summary "…" --category Roads \
    --source-name "Maharashtra PWD" --source-url https://… --expires 2026-11-05 --author "Name"
python3 tools/cms.py update publish <id> --approved-by "Name"      # high-risk items require this
python3 tools/cms.py candidate list                                 # leads from the source monitor
python3 tools/cms.py candidate approve <id> --approved-by "Name" --published-at 2026-10-03 --read-source
python3 tools/cms.py fact verify kumbh.snan.1 --verified-by "Name" --source-url https://…
python3 tools/cms.py build
```

Every write is validated; a change that would break the policy is rolled back with
the reason. Details: `data/README.md`.

## Kumbh lifecycle

`data/site-config.json` defines phases: preparation → mela_open → peak (live band
"NASHIK — LIVE") → extended → post_kumbh → evergreen. The homepage block, the nav
label and which Kumbh items count as live all follow the phase, so nothing is
hard-coded to August–September 2027. Set `kumbh.forcePhase` to preview a phase.
A daily workflow rebuilds so expiry and phase changes apply without a commit.

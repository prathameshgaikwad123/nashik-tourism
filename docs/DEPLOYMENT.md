# Deployment, automation and operations

## What is deployed

The contents of `nashiktourism/` — static files, no server code. Any static host works
(Cloudflare Pages, Netlify, GitHub Pages, S3+CDN…). Requirements:

* `/path/` serves `/path/index.html`; unknown paths serve `404.html` **with a 404 status**.
* Serve `.json`, `.xml`, `.webmanifest`, `.js` with their proper types; enable gzip/brotli.
* Cache `style.css`, `site.js`, `search.js`, `now.js` and images long-term **with versioned
  URLs or a short max-age**; they are not fingerprinted yet. Cache HTML for minutes, not days.
* **Redirects:** `nashiktourism/_redirects` is generated by `tools/build-seo-files.py` from
  `data/redirects.json` (every retired or mistyped URL) plus automatic no-trailing-slash and
  `.html` rules for every real page. All rules are 301. Cloudflare Pages and Netlify read this
  file from the web root. Other hosts need the same table in their own syntax. Add a row to
  `data/redirects.json` whenever a URL moves or is retired; never delete one.
* **www to apex** is a host rule that `_redirects` cannot express. Create it in Cloudflare
  (Rules > Redirect Rules): hostname equals `www.nashiktourism.com` -> dynamic redirect to
  `concat("https://nashiktourism.com", http.request.uri.path)`, status 301, preserve the query string.
* **robots.txt** is generated (`tools/build-seo-files.py`) and allows every search and AI
  retrieval crawler. **Keep Cloudflare's "Managed robots.txt" and "Block AI bots" OFF**, or
  Cloudflare prepends a block that disallows GPTBot, ClaudeBot, Google-Extended, CCBot and others.
* **llms.txt / llms-full.txt** are generated at the web root on every build (sections in `data/seo.json`).
* **IndexNow:** `data/indexnow-key.txt` holds the public key; the build writes `<key>.txt` to the web root.
  `.github/workflows/indexnow.yml` pings Bing after a push to `main`; run it by hand with
  `python3 tools/indexnow.py --submit --urls /path/ ...`.

## Environment variables and secrets

None are required to build or run the site. All are optional and read from the environment only.

| Name | Where | Purpose |
| `PR_TOKEN` | secret (monitor workflow) | Personal access token (`repo` scope) used to open the candidates PR. Only needed if you do not enable *Settings > Actions > General > Allow GitHub Actions to create and approve pull requests*; without either, the "Open a pull request" step fails with `GitHub Actions is not permitted to create or approve pull requests`. |
| `ANTHROPIC_API_KEY` | secret (monitor workflow) | Enables AI classification of detected changes. Without it the monitor still runs with heuristic candidates. |
| `NT_CLASSIFIER_MODEL` | variable | Model id for classification (default `claude-haiku-4-5-20251001`). |
| `NOTIFY_WEBHOOK_URL` | secret | Slack/Teams/Discord webhook for "candidates need review". |
| `INDEXNOW_KEY` | secret | Optional override of the IndexNow key. By default the key in `data/indexnow-key.txt` is used and its file is written on every build. |
| `NT_MSVALIDATE` | build variable | Bing Webmaster Tools verification code; emits `<meta name="msvalidate.01">` when set. |
| `NT_PLAUSIBLE_DOMAIN` / `NT_CF_BEACON_TOKEN` | build variable | Adds cookieless Plausible or Cloudflare Web Analytics when set. GA4 already runs. |
| `NT_SIGNUP_FORM_ACTION` / `NT_WHATSAPP_CHANNEL_URL` | build variable | Wires the "Kumbh 2027 updates" block to an email provider's form endpoint and/or a WhatsApp channel. With neither set it links to the contact form. |
| `NT_AFFILIATE_MAKEMYTRIP`, `_GOIBIBO`, `_BOOKING`, `_AGODA` | build variable | Affiliate query string (e.g. `affid=123`) appended to that partner's links. Unset = plain link. Links are always `rel="sponsored nofollow noopener"`. |

The `NT_*` build variables are read at build time. Set them as **repository variables** (Settings > Secrets and
variables > Actions > Variables); `ci.yml` and `daily-build.yml` pass them through. If your host builds the site
itself, set them there too, or the daily rebuild will remove what a host build added.
| `DAILY_REBUILD` | repository variable | Set to `false` to disable the daily rebuild workflow if your host rebuilds itself. |
| `NT_NOW` | local only | Pin the build clock (ISO timestamp) to preview any date, e.g. `NT_NOW=2027-08-02T09:00:00+05:30 python3 tools/build-all.py`. |

Weather uses Open-Meteo, which needs no key. Google Analytics keeps its existing
measurement ID in `tools/chrome.py`; `data/site-config.json > analytics.sitewide` is the
switch to add it to the legacy guides (off by default).

## Database migration

There is no database. The data layer is JSON in `data/`, versioned by git. Nothing to migrate.
If the owner later wants a database-backed editor, `tools/nt/store.py` is the only module that
reads and writes `data/`.

## Cron / automation

| Workflow | When | What it does |
|---|---|---|
| `ci.yml` | every push/PR | tests, data validation, full build, SEO/link audit, content-health artifact |
| `daily-build.yml` | 00:10 IST daily | rebuilds so expiry and Kumbh phases advance; commits only if output changed |
| `monitor-sources.yml` | every 6 hours | polls due sources, opens a PR with **candidates only** (nothing publishes) |
| `qa.yml` | weekly / manual | real-browser checks at 320–1920 px |

Search engines: `sitemap.xml` carries honest `lastmod` (the newest of a page's front-matter dates in `data/pages.json` and its change-log entries) and image entries; submit it once in Search Console.
`tools/indexnow.py --submit` notifies IndexNow engines of changed URLs (Google does not use IndexNow).

## Release checklist

1. `python3 tools/build-all.py` (validates data first)
2. `python3 -m unittest discover -s tools/tests`
3. `python3 tools/seo-check.py` — zero errors
4. Browser QA if layouts changed: `node tools/qa/viewports.js` with the server from `tools/qa/serve.py`
5. Deploy `nashiktourism/`; confirm `/sitemap.xml`, `/robots.txt` and a real 404.

## Outside the repo: do these after the pull request merges

1. **Cloudflare:** turn OFF Managed robots.txt and AI-bot blocking; add the www -> apex Redirect Rule above; purge the cache so `/robots.txt`, `/llms.txt`, `/_redirects` effects and the rebuilt pages are served fresh.
2. **Bing Webmaster Tools:** add and verify the site (set `NT_MSVALIDATE`, rebuild), submit `sitemap.xml`, and confirm IndexNow submissions are accepted.
3. **Google Search Console:** resubmit `sitemap.xml`; use URL Inspection > Request indexing on the rebuilt distance hub, the two new transport guides, the Bhandardara guide, the refreshed e-pass guide and the Kumbh hub; confirm the old 404 URLs now redirect (Validate fix on the 404 report).
4. **Set the repository variables** listed above (signup provider, affiliate parameters, analytics) when ready.
5. **Work through `VERIFY.md`** so figures can move from *Reported* to *Verified*; verifying the Kumbh dates unlocks `Event` rich results.
6. Approve the author bio, social profiles and the sponsored-content wording (see `VERIFY.md` section 7).
7. Add the real social profile URLs to `data/seo.json`.
